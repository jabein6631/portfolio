◆ About the Project

This project is a full-stack OTP-based authentication system designed to provide passwordless authentication using one-time passwords.

The system allows users to authenticate through either email or phone number, receive a six-digit OTP, verify the code, and access a protected dashboard after successful authentication. It protects against unauthorized access and provides a smooth, secure user experience.

◆ How It Works

01
User Request
User enters their email address or phone number (with country code) and selects the delivery mode.
02
Send OTP
Backend generates a 6-digit cryptographic OTP, hashes it with bcrypt (10 salt rounds), stores it with a 10-minute expiry, and dispatches via Brevo or Twilio.
03
Verify OTP
User enters the six-digit verification code. The system enforces a 60-second resend cooldown and validates submitted characters.
04
JWT Token Issuance
Upon successful bcrypt verification, the OTP record is purged, a user document is upserted, and a signed 7-day JWT token is returned to the client.
05
Protected Access
JWT is persisted client-side in LocalStorage. React router unlocks the authenticated Dashboard session and queries GET /api/auth/me.

◆ Security & Authentication Mechanisms

OTP Expiration & Rate Limiting

OTPs are stored with a strict 10-minute expiry time. In MongoDB, a TTL (Time-To-Live) index automatically purges expired records at the database level:

otpSchema.index({ expiresAt: 1 }, { expireAfterSeconds: 0 });

Endpoint /api/auth/send-otp is protected with express-rate-limit (max 10 requests per 15 mins per IP), with proxy trust enabled for Render.

Bcrypt Hashing & JWT Sessions

OTPs are never stored in plaintext. The backend creates a cryptographic salt (10 rounds) and stores the bcrypt hash:

const hashedOTP = await bcrypt.hash(otp, salt);

Upon verification, a JWT token signed with process.env.JWT_SECRET is issued with a 7-day expiration for stateless route authorization.

◆ Email & SMS Delivery Pipeline

The system intelligently routes OTPs depending on whether the user entered an email address or an international E.164 phone number:

EMAIL SERVICE HTTPS REST API

Nodemailer + Brevo HTTP API

Render free-tier instances restrict standard SMTP outbound traffic (ports 25, 465, 587). The implementation connects directly to Brevo's HTTP API (api.brevo.com/v3/smtp/email) over HTTPS port 443 with API key authentication, delivering custom HTML OTP templates reliably.

SMS SERVICE Twilio Telephony

Twilio Programmable SMS

For mobile authentications, the backend validates international format (^\+[1-9]\d{6,14}$) and dispatches via Twilio's official Node.js SDK (client.messages.create), delivering a 6-digit code with security warnings directly to the user's mobile device.

◆ Backend REST API Endpoints

Method Endpoint Purpose & Payload Action
POST /api/auth/send-otp Generate, hash, and dispatch 6-digit OTP to email or phone (Rate-limited).
POST /api/auth/verify-otp Validate 6-digit code against bcrypt hash, upsert user document, and return JWT token.
GET /api/auth/me Protected route returning authenticated user profile (Requires Authorization: Bearer <token>).

◆ What I Built (Engineering Contributions)

Frontend Architecture:

  • Email and phone authentication toggle interface with input masking.
  • 6-digit OTP entry with automated character formatting and countdown timer.
  • Protected dashboard with session details, avatar initials, and secure logout.

Backend & Security:

  • Cryptographic OTP generation with bcrypt hashing before persistence.
  • Rate limiting (10 requests per 15 minutes) with reverse proxy trust.
  • Dual delivery pipelines: Brevo HTTPS email + Twilio programmable SMS.

Technical Challenges

  • Render SMTP port blocking: Outbound SMTP is disabled on cloud free-tiers. Solved by integrating Brevo's HTTP API over port 443.
  • Reverse proxy rate limiting: Configured app.set("trust proxy", 1) so express-rate-limit correctly reads client IPs.
  • Database cleanup: Implemented MongoDB TTL indexes to automatically prune expired OTPs without cron jobs.

Key Learnings

  • Building resilient passwordless authentication workflows with multi-channel fallbacks.
  • Applying bcrypt cryptographic salting to ephemeral tokens to prevent DB leak exploits.
  • Cohesive full-stack React + Express architecture deployed to production on Render.
