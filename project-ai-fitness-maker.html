◆ About the Project

AI Fitness Maker is a full-stack fitness application designed to provide personalized workout and meal recommendations while using computer vision to analyze exercise movement in real time.

Built from the ground up to address the disconnect between static workout plans and real-time exercise execution, the application unifies user biometric profiling, BMI computation, goal selection, AI pose estimation, workout session tracking, and persistent session history into a single cohesive engineering workflow.

The Problem

Traditional fitness applications often rely on manual workout tracking and generic recommendations:

  • Users struggle with choosing suitable workouts for their body.
  • Lack of guidance on adhering to structured nutritional plans.
  • Manual rep tracking is tedious, distracting, and inaccurate.
  • No real-time feedback to detect improper form or posture errors.

The Solution

AI Fitness Maker combines personalized recommendations, workout tracking, and MediaPipe pose analysis into one workflow:

  • Calculates exact BMI and tailors custom meal and workout plans.
  • MediaPipe Pose tracks 33 skeletal landmarks via WebCam.
  • Automated repetition counting based on joint flexion and extension.
  • Persistent MongoDB storage for returning users and session stats.

08
MongoDB Atlas Persistence
Session data is synchronized to MongoDB via PATCH requests, appending to user profile history and updating weekly charts.

◆ Real-Time Pose Analysis (Computer Vision Engine)

The application uses MediaPipe Pose to detect 33 bodily landmarks from real-time camera input and evaluates joint angle geometry to power repetition counting and form feedback.

Biomechanics & Joint Angles

The angle θ between three connected landmark coordinates (A, B, C where B is the vertex) is calculated using the 2D arctangent formula:

θ = |atan2(Cy - By, Cx - Bx) - atan2(Ay - By, Ax - Bx)| * 180 / π

Key evaluated joints include Left Arm, Right Arm, Left Knee, and Right Knee.

Exercise Feedback Logic

  • Squats: Knee angle > 120° → "Squat deeper — break 90°"; < 60° → "Too deep — rise slightly"; 60°-120° → "Great squat depth!"
  • Push-ups: Arm angle < 50° → "Go lower — arms not deep enough"; > 178° → "Lock out arms fully at top".
  • Bicep Curls: Arm angle > 150° → "Curl the weight up more"; < 30° → "Perfect curl — now lower slowly".
  • Lunges: Front knee angle > 110° → "Lunge deeper — front knee at 90°".

◆ Backend Architecture & REST API Endpoints

The backend is built with FastAPI in Python, exposing a lightweight and robust REST API interface integrated with MongoDB Atlas:

Method Endpoint Purpose & Description
GET / Health check endpoint returning API status, database name, and collections.
POST /profiles Upsert user profile (name, age, gender, height, weight, goal, BMI). Auto-updates returning users.
GET /profiles/{name} Fetch stored profile by name (case-insensitive) for automatic login restoration.
POST /recommendations Compute BMI category and return tailored nutrition & workout plan.
POST /sessions Initialize new workout session document with exercise name and goal.
PATCH /sessions/{id} Incrementally sync completed reps, correct reps, posture errors, and session duration.
GET /sessions/user/{name} Retrieve full chronological workout history and performance stats for a user.
POST /pose/analyze Backend validation of joint angle landmarks with feedback generation.

◆ Data & Persistence (MongoDB Atlas)

Application state is persistently maintained across visits using a cloud-hosted MongoDB Atlas database named fitness containing two core collections:

📁 profiles Collection

Stores user biometric profile data keyed with name_lower for case-insensitive lookup, BMI, goal, and timestamps:

{ name, age, gender, height_cm, weight_kg, goal, bmi, bmi_category, created_at, updated_at }

📁 sessions Collection

Tracks each completed or in-progress workout session with granular metrics:

{ user_name, exercise_name, goal, reps_completed, correct_reps, wrong_pose_events, duration_seconds, started_at }

◆ What I Built (Engineering Contributions)

Frontend & UI/UX:

  • Single-page architecture with dynamic screen transitions.
  • Real-time BMI calculation preview with category gauge.
  • Workout dashboard with KPIs and weekly activity charts.

Computer Vision & Backend:

  • MediaPipe Pose integration with real-time landmark canvas.
  • FastAPI REST API with 8 endpoints and Pydantic validation.
  • MongoDB Atlas integration with case-insensitive upserts.

Technical Challenges

  • Low-latency frame rates: Running 33 3D skeletal landmark extraction smoothly inside the client browser without freezing the UI thread.
  • Rep counting noise: Filtering sensor jitter and incomplete body extensions to avoid false positive repetitions.
  • State synchronization: Managing real-time telemetry syncing with the FastAPI backend without flooding the network.

Key Learnings

  • Designing clean, idiomatic REST API schemas with FastAPI and Pydantic.
  • Applying vector mathematics to computer vision landmarks for motion validation.
  • Deploying decoupled frontend and backend services on Render using automated blueprint configurations.
